# open-data-ai-analytics

## Мета
Створити модульний проєкт для аналізу відкритих даних про дорожньо-транспортні пригоди (ДТП) та відпрацювати роботу з Git: гілки, коміти, Pull Request, злиття в main, вирішення merge-конфліктів і створення тегу релізу.

## Джерело відкритих даних
Набір відкритих даних (ДТП 2015) з порталу data.gov.ua:  
https://data.gov.ua/dataset/dtp2015/resource/5f479fab-2e01-42d6-932d-3748d32d3a09

## Питання / гіпотези для аналізу

1. **Сезонність:** кількість ДТП протягом року нерівномірна - у певні місяці/пори року ДТП більше.
2. **Час доби:** найбільша кількість ДТП припадає на години пікового руху (ранок/вечір).
3. **Фактори тяжкості:** частка ДТП з постраждалими/загиблими (або важкими наслідками) залежить від типу/причини ДТП та умов (за наявності відповідних полів у наборі).

## Модулі проєкту
- `data_load` - завантаження даних
- `data_quality_analysis` - перевірка якості даних
- `data_research` - дослідження/аналіз даних
- `visualization` - візуалізація результатів

## Структура репозиторію
- `data/` - дані та опис
- `notebooks/` - ноутбуки для EDA/аналізу
- `src/` - вихідний код модулів
- `reports/figures/` - збережені графіки




# Open Data AI Analytics — Lab 3

Контейнеризований проєкт для аналізу відкритих даних із використанням Docker Compose, PostgreSQL, Python та Flask.

## Опис проєкту

У межах лабораторної роботи №3 було реалізовано контейнеризовану систему для аналізу відкритих даних. Проєкт складається з кількох окремих сервісів, кожен із яких виконує свою функцію: завантаження даних, перевірка якості, базове дослідження, побудова візуалізацій та відображення результатів через веб-інтерфейс.

Усі сервіси запускаються через Docker Compose, взаємодіють між собою через базу даних PostgreSQL, а результати зберігаються у спільних директоріях.

## Опис сервісів
###db
Контейнер із базою даних PostgreSQL. Використовується для зберігання набору даних та передачі даних між модулями проєкту.

###data_load
Сервіс завантаження даних. Виконує такі дії:

- зчитує CSV-файл;
- створює таблицю в базі даних;
- імпортує записи у PostgreSQL;
- формує файл load_report.json.
- data_quality_analysis


###Сервіс перевірки якості даних. Виконує такі дії:

- визначає кількість пропущених значень;
- перевіряє дублікати;
- визначає типи даних;
- формує звіт quality_report.json.
- data_research


### Сервіс базового дослідження даних. Виконує такі дії:

- аналізує набір даних;
- обчислює базові характеристики;
- формує звіт research_summary.json.
- visualization


### Сервіс побудови візуалізацій. Виконує такі дії:

- зчитує дані з PostgreSQL;
- будує щонайменше два графіки;
- зберігає результати у папку plots.
- web


###Сервіс веб-інтерфейсу. Виконує такі дії:

- запускає веб-застосунок Flask;
- зчитує результати з папок reports і plots;
- відображає результати завантаження, перевірки якості, дослідження та візуалізації через браузер.

## Команди запуску
1. Перехід у директорію проєкту
**cd open-data-ai-analytics**
2. Перехід на гілку лабораторної роботи №3
**git checkout feature/docker-lab3**
3. Створення конфігураційного файлу .env
**cp .env.example .env**
4. Запуск усіх сервісів
**docker compose up --build**
5. Перевірка стану контейнерів
**docker compose ps -a**
6. Зупинка системи
**docker compose down -v**

###Перелік портів
5432 - порт бази даних PostgreSQL (db)
8000 - порт веб-інтерфейсу (web)
